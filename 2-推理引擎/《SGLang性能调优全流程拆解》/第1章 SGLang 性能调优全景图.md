## 1. SGLang 性能调优全景图：课程介绍、性能指标定义、调优方法论总览

大家好，我是你们这趟调优之旅的向导。说实话，第一次接触 SGLang 的时候，我也被它那套复杂的参数和调度逻辑搞得有点懵。但摸爬滚打几年下来，我逐渐摸清了它的脾气。今天这第一讲，咱们不急着上手调参数，先把地图摊开，看看 SGLang 性能调优到底是个什么玩意儿。

说白了，调优就是一场「找瓶颈、拆瓶颈」的游戏。你想想看，大模型推理就像一条流水线，从用户输入到吐出第一个 token，再到后面源源不断地生成，每个环节都可能卡住。我们的任务，就是把这些卡点一个个揪出来，然后干掉它们。

### 1.1 课程介绍：我们到底要学什么？

这门课不是讲 SGLang 怎么安装、怎么跑 demo 的。那些官方文档写得比我清楚。我们要聊的，是当你把模型部署上去之后，发现延迟高得离谱、吞吐量上不去、GPU 利用率只有 30% 的时候，该怎么办。

我个人习惯把调优分成三个层次：

- **第一层：看得懂指标** —— 你得知道用什么尺子量问题。
- **第二层：找得到瓶颈** —— 是显存不够？是计算卡在某个算子？还是调度策略太傻？
- **第三层：下得去手优化** —— 改参数、换策略、甚至动代码。

这门课会覆盖从单机单卡到多机多卡的各种场景。嗯，这里要注意，我不会给你一堆「万能参数」，因为根本不存在那种东西。每个场景、每个模型、每个硬件，最优解都不一样。我会教你的是——怎么自己找到那个最优解。

### 1.2 性能指标定义：拿什么衡量好坏？

做调优，第一件事就是统一度量衡。我见过太多人上来就调参数，调了半天发现「优化」了个寂寞，因为连目标指标都没搞清楚。下面这四个指标，是 SGLang 调优的核心，你必须刻在脑子里。

#### 1.2.1 首 Token 延迟（TTFT：Time To First Token）

这是用户最直观的感受。你问模型一个问题，它多久才开始回答？这个时间就是 TTFT。它主要受 prefill 阶段（预填充阶段）的影响，说白了就是模型在「读题」和「构思」的时间。

**为什么重要？** 如果 TTFT 超过 2 秒，用户就会觉得「卡住了」。我在做实时对话系统时，TTFT 是我们的第一优化目标。

#### 1.2.2 吞吐量（Throughput）

单位时间内能处理多少个请求，或者能生成多少个 token。这个指标决定了你的系统能服务多少人。对于离线批处理任务，吞吐量就是王道。

**注意：** 吞吐量和延迟往往是矛盾的。你拼命压吞吐，单个请求的延迟就会飙升。怎么平衡？这是后面章节的重点。

#### 1.2.3 每个 Token 的延迟（ITL：Inter-Token Latency）

模型吐出第一个 token 之后，每生成一个后续 token 需要多长时间。这个指标决定了模型的「语速」。ITL 越稳定、越小，用户体验越好。

我曾经遇到过一个 case，TTFT 只有 300ms，但 ITL 忽高忽低，从 20ms 跳到 200ms。用户反馈说「模型说话一顿一顿的」，这就是 ITL 不稳定导致的。

#### 1.2.4 综合指标对比

为了方便你理解，我整理了一个表格：

|指标|全称|关注点|典型优化方向|
|---|---|---|---|
|TTFT|Time To First Token|响应速度|Prefill 加速、KV Cache 预填充|
|Throughput|吞吐量|系统容量|动态批处理、显存复用|
|ITL|Inter-Token Latency|生成流畅度|Decode 阶段优化、算子融合|

```
核心原则： 不要试图同时优化所有指标。先明确你的业务场景——是实时对话（优先 TTFT 和 ITL），还是离线批量生成（优先吞吐量）。
```

### 1.3 调优方法论总览：从哪下手？

好，指标清楚了，接下来就是方法论。我总结了一套「四步走」的调优流程，这些年一直在用，屡试不爽。

#### 1.3.1 第一步：建立基线

别一上来就改参数。先用默认配置跑一遍，记录下 TTFT、吞吐量、ITL、显存占用、GPU 利用率。这个基线数据是你后续所有优化的参照物。

**避坑指南：** 我曾经跳过这一步，直接调了 batch size，结果发现性能反而下降了。后来一查，原来是基线数据没记录，我根本不知道「优化」前的真实水平。

#### 1.3.2 第二步：定位瓶颈

用 profiling 工具（比如 Nsight Systems、PyTorch Profiler）看看时间都花在哪了。是 prefill 阶段慢？还是 decode 阶段慢？是计算瓶颈（算力打满）？还是访存瓶颈（显存带宽不够）？

这里有个小技巧：看 GPU 利用率。如果利用率低于 80%，大概率是调度或数据传输在拖后腿。

#### 1.3.3 第三步：针对性优化

找到瓶颈后，对症下药。比如：

- **TTFT 高：** 检查 prefill 的 batch size 是否合理，考虑使用 RadixAttention 或 Prefix Caching。
- **吞吐量低：** 增大 max_num_batched_tokens，或者启用动态批处理。
- **ITL 不稳定：** 检查 decode 阶段的调度策略，考虑使用 FlashInfer 的优化 kernel。

#### 1.3.4 第四步：验证与迭代

每次只改一个参数，改完重新跑基线测试。对比数据，看指标是变好了还是变差了。记住，调优是一个循环，不是一锤子买卖。

**我的经验：** 每次优化后，把配置和结果记录在一个文档里。三个月后你回头看，会发现这些记录比你的记忆靠谱一万倍。
