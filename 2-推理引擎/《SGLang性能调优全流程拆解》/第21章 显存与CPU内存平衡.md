## 21. 显存与CPU内存平衡：CPU Offloading 策略、NVLink vs PCIe 带宽影响、统一内存管理

显存不够用，是做大模型推理时最头疼的问题之一。

我见过不少团队，模型刚加载完，显存就爆了。然后就开始各种折腾——换卡、降精度、甚至砍模型层数。其实，很多时候我们不需要那么极端。CPU Offloading 就是一个很实用的折中方案。

### CPU Offloading 策略：什么时候该卸，什么时候不该卸

CPU Offloading 说白了，就是把一部分模型参数或中间结果放到 CPU 内存里，等 GPU 需要时再搬回来。代价就是速度变慢，但能跑更大的模型。

**核心原则：** 只 offload 那些不常被访问的层。

- **Embedding 层：** 词表很大时，Embedding 矩阵占显存不少。但它的访问模式是稀疏的，每次只取几个 token 的向量。我个人习惯把 Embedding 放到 CPU 上，推理时按需拉取。
- **Attention 的 KV Cache：** 这个千万别 offload。KV Cache 是逐 token 生成的，每个 step 都要读写，延迟敏感度极高。我曾经试过把 KV Cache 放 CPU，结果推理速度直接掉了 10 倍，完全不可用。
- **FFN 中间层：** 如果你的模型有 100 层以上，可以考虑把最后几层 FFN 的权重 offload 到 CPU。因为长序列推理时，前面层的计算更密集，后面层相对空闲。

```
避坑指南： 我曾经在 70B 模型上做过一次全量 offload，就是把所有参数都放 CPU。结果呢？每个 token 生成都要等几十毫秒去搬数据，吞吐量惨不忍睹。后来我改成只 offload 最后 10 层，效果好了很多。
```

### NVLink vs PCIe 带宽影响：数据搬运的瓶颈

Offloading 好不好用，很大程度上取决于 CPU 和 GPU 之间的带宽。这里有两个关键通道：PCIe 和 NVLink。

|通道类型|典型带宽|延迟|适用场景|
|---|---|---|---|
|PCIe 4.0 x16|32 GB/s|~1-2 μs|单卡 offload，数据量不大时|
|PCIe 5.0 x16|64 GB/s|~1 μs|新一代服务器，带宽翻倍|
|NVLink (H100)|900 GB/s|~0.1 μs|多卡间通信，或 GPU 直连 CPU 内存|

你想想看，PCIe 4.0 的 32 GB/s 和 NVLink 的 900 GB/s，差了将近 30 倍。这意味着什么？

- 如果你用 PCIe 做 offload，搬一个 10GB 的权重需要 0.3 秒。这个时间足够 GPU 做几十次前向推理了。
- 如果用 NVLink，同样的数据只要 11 毫秒。嗯，这个开销就小多了。

**我的建议：** 如果服务器支持 NVLink，优先用它做 offload。如果只有 PCIe，那就尽量少搬数据，或者用异步传输来掩盖延迟。

**小技巧：** 在代码里可以用 `torch.cuda.Stream` 来异步执行数据传输。这样 GPU 在搬数据的同时还能继续算，不会完全卡住。

### 统一内存管理：让系统自己决定放哪

统一内存（Unified Memory）是 CUDA 提供的一个特性。它让 CPU 和 GPU 共享一个虚拟地址空间，系统自动在两者之间迁移数据。

听起来很美好对吧？但实际用起来，坑不少。

- **优点：** 代码写起来简单，不用手动管理 cudaMemcpy。系统会根据访问模式自动迁移。
- **缺点：** 迁移策略是黑盒的。系统可能在你最需要性能的时候，突然把数据搬走。我遇到过几次，推理到一半，显存里的数据被换到 CPU 了，然后性能断崖式下跌。

**什么时候用统一内存？**

- 模型调试阶段，快速验证功能时。
- 数据访问模式非常不规则，手动管理太复杂时。
- 显存和 CPU 内存比例接近 1:1，系统有足够空间做缓存时。

**什么时候别用？**

- 生产环境，对延迟有严格要求的场景。
- 模型很大，显存几乎占满时。这时候系统没有余量做缓存，反而会频繁触发 page fault。

**注意：** 统一内存的 page fault 开销很大。如果频繁触发，性能可能比纯 CPU 计算还差。我建议在关键路径上，还是用手动 offload 更可控。

### 实战建议：怎么配最合理

根据我自己的经验，给几个具体的配置建议：

- **单卡场景（如 A100 80GB）：** 跑 13B 模型完全不用 offload。跑 70B 模型时，把 Embedding 和最后 5 层 FFN 放 CPU，用 PCIe 异步传输。
- **多卡场景（如 8×H100）：** 用 NVLink 做 tensor parallelism，模型参数分散在多卡显存中。如果显存还是不够，把 Embedding 放到 CPU 上，用 NVLink 直连 CPU 内存。
- **统一内存：** 只在调试阶段用。生产环境一定要手动管理，避免 page fault 导致的性能抖动。

```
一句话总结： Offloading 是显存不够时的救命稻草，但别滥用。优先 offload 不常访问的层，用 NVLink 减少搬运开销，生产环境别依赖统一内存。
```
