## 第二章：环境与基准测试搭建

说实话，很多人在SGLang调优上栽跟头，不是因为模型选得不对，也不是参数调得不好。而是——环境没搭对。我见过太多人花了两天时间调优，最后发现是CUDA版本不匹配，性能直接腰斩。所以这一章，咱们先把地基打牢。

### 2.1 GPU驱动与CUDA：别小看这一步

先说说GPU驱动。我个人习惯是，装驱动之前先查一下当前系统支持的驱动版本上限。你想想看，驱动装太高，老卡不支持；装太低，新特性用不了。我建议用 `nvidia-smi` 先看一眼当前状态：

```
nvidia-smi
# 查看驱动版本、CUDA版本、GPU型号
```

然后就是CUDA。这里有个坑——SGLang对CUDA版本其实挺挑剔的。我踩过这个坑：之前用CUDA 11.8跑一个比较新的模型，结果编译时各种报错。后来换成12.1，一次过。

**⚠️ 注意：** 不要直接用系统包管理器装CUDA。我建议去NVIDIA官网下载runfile安装，这样能精确控制版本。用apt装容易装成旧版。

装完之后，记得配环境变量：

```
export PATH=/usr/local/cuda-12.1/bin:$PATH
export LD_LIBRARY_PATH=/usr/local/cuda-12.1/lib64:$LD_LIBRARY_PATH
```

验证一下：

```
nvcc --version
# 应该输出12.1或你装的版本
```

### 2.2 PyTorch环境：版本匹配是关键

PyTorch版本和CUDA版本必须一一对应。我建议用conda创建独立环境，别跟系统Python混在一起。为什么呢？因为不同项目可能依赖不同版本的PyTorch，混在一起迟早出问题。

```
conda create -n sglang_env python=3.10
conda activate sglang_env
pip install torch==2.1.0 --index-url https://download.pytorch.org/whl/cu121
```

这里有个小技巧：装完之后跑一下这个脚本，确认GPU能用：

```
import torch
print(torch.cuda.is_available())  # 应该输出True
print(torch.cuda.device_count())  # 输出GPU数量
print(torch.cuda.get_device_name(0))  # 输出GPU型号
```

**💡 提示：** 如果 `torch.cuda.is_available()` 返回False，别急着重装。先检查一下CUDA环境变量有没有配对。我曾经因为LD_LIBRARY_PATH写错了，折腾了半小时。

### 2.3 安装SGLang：从源码还是pip？

SGLang有两种安装方式：pip安装和源码编译。我个人建议，如果是第一次用，先pip装一个稳定版：

```
pip install sglang[all]
```

但如果你要做性能调优，我强烈建议从源码编译。为什么呢？因为编译时你可以打开一些优化选项，比如FlashAttention、vLLM的PagedAttention等。这些在pip包里可能默认没开。

```
git clone https://github.com/sgl-project/sglang.git
cd sglang
pip install -e ".[all]"
```

编译时间大概5-10分钟，喝杯咖啡的功夫。

### 2.4 建立基准测试：用数据说话

环境搭好了，接下来就是跑基准测试。没有基线数据，你后面做的所有优化都是盲人摸象。我习惯用SGLang自带的benchmark工具，因为它跟SGLang的调度器、内存管理深度绑定，测出来的数据更真实。

先跑一个最简单的测试：

```
python -m sglang.benchmark --model meta-llama/Llama-2-7b-chat-hf --batch-size 1 --input-len 512 --output-len 128
```

这个命令会输出几个关键指标：

- **吞吐量** ：每秒处理的请求数
- **延迟** ：P50、P95、P99延迟
- **显存占用** ：峰值显存

我建议把结果记下来，存到一个表格里。后面每次优化完，都拿这个基线对比。

|指标|基线值|优化后|提升比例|
|---|---|---|---|
|吞吐量 (req/s)|12.3|—|—|
|P50延迟 (ms)|45.2|—|—|
|P99延迟 (ms)|102.1|—|—|
|峰值显存 (GB)|14.3|—|—|

### 2.5 多维度测试：别只测一种场景

只测一个batch size、一个输入长度，数据太片面了。我建议至少测三种场景：

1. **小请求场景** ：batch size=1, input_len=128, output_len=32。模拟实时对话。
2. **中等请求场景** ：batch size=8, input_len=512, output_len=128。模拟批量推理。
3. **大请求场景** ：batch size=32, input_len=1024, output_len=256。模拟离线处理。

跑完这三个场景，你就能对SGLang的性能有个全面认识。我一般还会加一个压力测试：逐渐增加并发数，直到系统出现OOM或者延迟飙升。这个极限值就是你的系统瓶颈。

```
🔑 关键点： 基准测试不是跑一次就完事了。每次改完配置、换完模型、升级完驱动，都要重新跑一遍。我习惯把每次的测试结果都存下来，用日期命名文件夹。这样回头查问题的时候，能快速定位是哪次改动导致了性能变化。
```

### 2.6 知识体系总览

下面这张图，把本章的核心逻辑串起来了。你可以把它当作一个检查清单：

环境与基准测试搭建流程 第一步：环境搭建 GPU驱动 → CUDA 12.1 → PyTorch 2.1.0 → SGLang（推荐源码编译） 第二步：验证环境 nvidia-smi → nvcc --version → torch.cuda.is_available() 第三步：基准测试 小请求场景 → 中等请求场景 → 大请求场景 → 压力测试 第四步：记录基线数据（吞吐量、延迟、显存）

嗯，到这里，环境搭建和基准测试就搞定了。你手头应该已经有了一份可靠的基线数据。后面所有的优化，都要拿这份数据来对比。没有基线，优化就是瞎忙活。

**💡 我的习惯：** 每次跑完基准测试，我会把结果截图保存，同时在代码仓库里建一个 `benchmark_results/` 文件夹，把日志文件也存进去。这样万一哪天要回溯，直接翻文件夹就行。
