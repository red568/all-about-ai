## 课程定位

理解 DDTree：Diffusion Draft Tree 与树验证，需要先回答“如何在固定节点预算下构造候选树并控制树验证成本？”。本课沿着概念边界、性能关系、实现证据和发布条件四条线展开，其中 Diffusion Draft Tree 与树节点预算是最先核对的状态。工作负载、模型修订、运行时、资源余量和服务承诺共同决定树结构用共享前缀表达多个并行候选序列是否值得采用，后续每个结论都会注明这些条件。

实验采用两条证据路径。CPU 机制模拟隔离 Diffusion Draft Tree 与树节点预算的因果关系；真实 CUDA 路径记录实现、框架和硬件开销。报告分别标记两类结果，节点利用率的模拟值不充当 GPU 基准，单台设备的绝对速度也不外推。最终结论必须能够复现、诊断并回滚。

## 学习目标

1. 准确解释 Diffusion Draft Tree、树节点预算和分支因子之间的状态与资源关系。
2. 使用“Value(node) = P(prefix survives)\*P(token)\*SavedTargetTime - VerifyMarginalCost”建立可计算的收益边界并解释全部变量。
3. 围绕节点利用率、路径存活概率、覆盖率和单位节点收益设计可复现实验。
4. 识别宽树包含大量低概率节点、深树在前部拒绝后全部浪费和验证掩码构造占据 CPU 关键路径等典型失败模式。
5. 对“如何在固定节点预算下构造候选树并控制树验证成本？”给出包含适用条件、证据、风险和回滚的工程答案。

## 知识串讲

### 核心直觉与基础关系

### 核心直觉：把被丢掉的第二名候选重新利用

假设 DFlash 输出：

```
位置1: A 0.70 / B 0.20
位置2: C 0.60 / D 0.30
位置3: E 0.55 / F 0.35
```

线性 Draft 只会验证：

```
A → C → E
```

但如果 Target 第 2 个位置更偏好 D，那么整条线性后缀很快被截断。

树可以覆盖：

```
A
   /   \
  C     D
 / \   / \
E  F  E   F
```

只要真实 Target path 落在树中，就可能继续接受更多 token。

### 候选树不是笛卡尔积

如果每个位置保留 $b$ 个 token，深度 $K$ 的完整树节点量近似：

$$
N=\sum_{d=1}^{K}b^d
$$

$b=4,K=8$ 时已经不可接受。

因此 DDTree 需要在有限 Node Budget $B$ 下选择“最值得验证”的分支。

可以定义一条路径的 surrogate probability：

$$
Score(path)=\prod_{k}q_k(x_k)
$$

或用 log：

$$
\log Score(path)=\sum_k\log q_k(x_k)
$$

再用 best-first / heap 等方式逐步扩展高分路径，直到耗尽节点预算。

### 为什么 Diffusion Marginal 与 AR Prefix 有错位

这里有一个很重要的概念边界。

Diffusion Drafter 的每位置分布可能更多反映“在整个 block 条件下这个位置像什么”，而 Target AR verifier 的接受是严格 prefix-based：

```
第3个 token 是否有效
必须建立在第1、2个 token 都属于同一正确前缀
```

因此 marginal probability 不是完美的路径概率。

这也是后续 PRESTO/CaDDTree 类工作继续优化 tree scoring / cost-aware budget 的原因。

### Tree Verification

Target 一次 forward 需要让每个节点只能看到自己的祖先，而不能看兄弟分支。

因此构造 ancestor-only attention mask：

```
Root
├─ A
│  ├─ C
│  └─ D
└─ B
   ├─ E
   └─ F
```

节点 `D` 可以看 `Root,A,D` ，不能看 `C` 。

如果 mask 错误，让一个分支看见兄弟节点，会破坏 causal semantics，验证结果不再对应真实自回归路径。

### Node Budget 的性能模型

树越大，覆盖率通常越高：

$$
E[A(B)]\uparrow
$$

但 verification cost 也增加：

$$
T_V(B)\uparrow
$$

所以真正目标：

$$
Throughput(B)=\frac{E[A(B)]}{T_D+T_{tree}(B)+T_V(B)}
$$

这解释了为什么固定“大树”并不合理，后续 cost-aware tree 会直接以 throughput 而不是 accepted length 作为目标。

### DDTree 与 EAGLE Tree 的区别

EAGLE 类 tree 往往来自 autoregressive/feature drafter 的分支 rollout；DDTree 利用 block diffusion 一次得到的 per-position distributions 构树。

共同点：

- 都要在有限节点下覆盖高概率路径；
- 都要 Target tree verification；
- 都需要严格 causal/ancestor mask。

差异：

- 候选概率的语义不同；
- Draft cost 结构不同；
- 路径 scoring 的可靠性不同。

### Diffusion Draft Tree

对 Diffusion Draft Tree 做边界检查，要覆盖输入、输出、状态归属和销毁时点。DDTree：Diffusion Draft Tree 与树验证的等待、计算及复制都能沿这些节点定位。Diffusion Draft Tree 传给树节点预算的数据还应附带模型或策略版本，使测量结果可以对应到唯一配置。

Diffusion Draft Tree 的资源账要拆成计算、显存、内存带宽、主机开销和同步等待。固定节点预算在深度与宽度之间分配通常只先改变其中几项，其他资源随后可能进入关键路径。Diffusion Draft Tree 的请求时间线和资源曲线可以呈现这种转移，平均 GPU 利用率只作为辅助信号。

工作负载一变，Diffusion Draft Tree 对系统的贡献也会变化。构造验证掩码应覆盖长短输入、不同输出、并发、突发、采样与任务域，并保留低载、稳定高载和过载记录。容量判断不能从一次固定批量的短运行外推。

对 Diffusion Draft Tree 的优化只有在输出合同不变时才有效。Token 序列、采样分布、结构合法性、结束原因和错误传播均需对账。节点重排破坏内存连续性会触发停止与回退，系统恢复到已有证据支持的配置。

Diffusion Draft Tree 相关事件要能关联到稳定请求身份、模型与策略版本、开始结束时间、阶段耗时、资源采样和失败原因。掩码构造时间必须附带口径。缺少这些信息时，关于“如何在固定节点预算下构造候选树并控制树验证成本？”的判断无法在上线后复核。

### 树节点预算

在 DDTree：Diffusion Draft Tree 与树验证中，树节点预算的边界由输入、输出、状态和拥有者共同确定。把生命周期写清楚，才能定位请求在哪个阶段等待、计算或复制。树节点预算连接分支因子时还要传播身份和版本，避免把另一套配置的结果归到当前实验。

测量树节点预算时分别记录算力、显存、带宽、CPU 开销与同步。发生“节点存活概率沿路径相乘并快速衰减”后，缩短的阶段可能让另一项资源成为瓶颈。分析因此对齐树节点预算的阶段事件和资源轨迹，不让单个平均利用率代替因果证据。

### 失败模式 1：宽树包含大量低概率节点

“宽树包含大量低概率节点”的即时动作是限制影响面：撤掉候选、缩小预算、隔离流量、执行过载拒绝或恢复稳定修订。根因修复需补充适用的输入检查、迟滞、版本关系、资源余量和门禁。随后用同一失败输入复验验证节点数。

### 失败模式 2：深树在前部拒绝后全部浪费

针对“深树在前部拒绝后全部浪费”，保留失败现场并核验请求身份、模型修订、策略、负载分布与统计窗口。树节点预算的时间线配合路径存活概率、覆盖率可区分选择错误、执行异常、验证失败和计量偏差。三方完成数无法对齐时不发布性能判断。

对“深树在前部拒绝后全部浪费”先执行在线保护，再处理复发条件。面向深树在前部拒绝后全部浪费的保护从禁用候选、预算收缩、请求隔离、过载拒绝和稳定回退中选择；长期措施落实到校验、迟滞、版本绑定、容量余量或自动门禁。原样本重放时同时检查掩码构造时间的采集完整性。

### 失败模式 3：验证掩码构造占据 CPU 关键路径

“验证掩码构造占据 CPU 关键路径”的排查从证据一致性开始：请求、模型、策略、输入输出分布和测量窗口必须对应同一次运行。检查分支因子的阶段事件，并用覆盖率及验证节点数缩小故障位置。客户端、服务端、计费数据均需完成对账。

修复“验证掩码构造占据 CPU 关键路径”分为影响控制和复验。针对验证掩码构造占据 CPU 关键路径可以撤回候选、降低预算、隔离请求、拒绝过载或切换稳定路径；复发预防补齐输入校验、迟滞、版本绑定、容量余量及门禁。重放同一失败样本后，核对 KV 重排时间没有被隐藏。

### 失败模式 4：节点重排破坏内存连续性

记录到“节点重排破坏内存连续性”时，冻结配置和工作负载，确认请求身份、模型及策略修订、长度分布和时间窗口。沿前缀共享回放事件，再比较验证节点数与掩码构造时间。若完成数存在账差，先修复计量链。

处理“节点重排破坏内存连续性”时先保护在线请求，可采用禁用候选、收紧预算、隔离请求、拒绝过载或回退稳定路径。后续通过输入校验、迟滞、版本绑定、容量余量或自动门禁降低复发概率。修复完成后重放原失败样本，并确认接受长度没有转移到未计量层。

### 失败模式 5：候选缺少多样性

排查“候选缺少多样性”需要同一版本、同一请求分布和同一统计窗口。先复核请求身份、模型与策略，再查看树验证的时间线以及掩码构造时间、KV 重排时间。选择、执行、验证、计量四个环节逐一排除，并核对三方完成数。

“候选缺少多样性”的即时动作是限制影响面：撤掉候选、缩小预算、隔离流量、执行过载拒绝或恢复稳定修订。根因修复需补充适用的输入检查、迟滞、版本关系、资源余量和门禁。随后用同一失败输入复验单位节点收益。

### 失败模式 6：树预算静态而负载动态

诊断“树预算静态而负载动态”时，先核对请求身份、模型修订、策略配置、输入输出分布和测量窗口。沿时间线检查节点存活概率，结合 KV 重排时间与接受长度定位工作选择、执行、验证或计量环节。客户端、服务端和计费完成数未对账前暂停性能结论。

对“树预算静态而负载动态”先执行在线保护，再处理复发条件。面向树预算静态而负载动态的保护从禁用候选、预算收缩、请求隔离、过载拒绝和稳定回退中选择；长期措施落实到校验、迟滞、版本绑定、容量余量或自动门禁。原样本重放时同时检查节点利用率的采集完整性。

```
"""Lesson 07 — explicit candidate-tree construction and leaf verification."""

from __future__ import annotations

import argparse
from collections import deque

from phase3lab.shared.cuda_ops import cuda_environment, load_causal_lm, timed_cuda
from phase3lab.shared.runner import LabSpec, run_cli
from phase3lab.shared.stats import latency_summary

SPEC = LabSpec(
    lab_id="lesson-07-diffusion-tree",
    title="Diffusion Draft Tree：树预算、叶路径与批量验证",
    goal="把候选树保存为父子关系，展开叶路径并用同一 Target 批量验证。",
    real_evidence=("tree nodes and parents", "leaf paths", "Target verification scores"),
    required_inputs=("causal LM", "CUDA GPU"),
    outputs=("tree topology", "leaf acceptance", "verification latency"),
    acceptance=("tree has no cycles", "every leaf path is reconstructable", "all leaves are verified"),
)

def add_arguments(parser: argparse.ArgumentParser) -> None:
    parser.add_argument("--tree-depth", type=int, default=3)
    parser.add_argument("--branching", type=int, default=2)
    parser.add_argument("--repeats", type=int, default=4)

def build_tree(token_pool: list[int], depth: int, branching: int) -> tuple[list[dict], list[list[int]]]:
    if depth < 1 or branching < 1:
        raise ValueError("tree depth and branching must be positive")
    nodes = [{"id": 0, "parent": None, "token_id": None, "depth": 0}]
    queue = deque([0])
    while queue:
        parent_id = queue.popleft()
        parent = nodes[parent_id]
        if parent["depth"] >= depth:
            continue
        for offset in range(branching):
            node_id = len(nodes)
            token = token_pool[(node_id + offset) % len(token_pool)]
            nodes.append({"id": node_id, "parent": parent_id, "token_id": token, "depth": parent["depth"] + 1})
            queue.append(node_id)
    leaves = [node for node in nodes if node["depth"] == depth]
    paths = []
    for leaf in leaves:
        path = []
        current = leaf
        while current["parent"] is not None:
            path.append(current["token_id"])
            current = nodes[current["parent"]]
        paths.append(list(reversed(path)))
    return nodes, paths

def fixture(args: argparse.Namespace) -> dict:
    nodes, paths = build_tree([7, 11, 19, 23], args.tree_depth, args.branching)
    return {"nodes": nodes, "leaf_paths": paths, "leaf_count": len(paths), "acyclic": all(node["parent"] is None or node["parent"] < node["id"] for node in nodes)}

def real(args: argparse.Namespace) -> dict:
    torch, tokenizer, model, load = load_causal_lm(args.model)
    prefix = tokenizer(args.prompt, return_tensors="pt").input_ids.to("cuda")
    with torch.inference_mode():
        logits = model(prefix, use_cache=False).logits[:, -1, :]
    pool = torch.topk(logits, k=max(2, args.branching * 2), dim=-1).indices[0].tolist()
    nodes, paths = build_tree(pool, args.tree_depth, args.branching)
    leaf_tokens = torch.tensor(paths, device="cuda")
    batch = torch.cat([prefix.repeat(len(paths), 1), leaf_tokens], dim=1)
    start = prefix.shape[1] - 1
    with torch.inference_mode():
        samples, target_logits = timed_cuda(torch, lambda: model(batch, use_cache=False).logits[:, start:start + args.tree_depth, :], warmups=1, repeats=args.repeats)
    predictions = torch.argmax(target_logits, dim=-1).tolist()
    acceptance = []
    for path, predicted in zip(paths, predictions):
        count = 0
        for proposed, expected in zip(path, predicted):
            if proposed != expected:
                break
            count += 1
        acceptance.append(count)
    return {
        "environment": cuda_environment(torch),
        "load_ms": load,
        "nodes": nodes,
        "leaf_paths": paths,
        "accepted_depths": acceptance,
        "verification_latency": latency_summary(samples),
    }

def main() -> None:
    run_cli(SPEC, add_arguments, real, fixture)

if __name__ == "__main__":
    main()
```
