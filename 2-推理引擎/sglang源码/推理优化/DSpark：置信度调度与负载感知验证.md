## 知识串讲

### 核心直觉与基础关系

### 核心直觉：Semi-Autoregressive 不是回到完整 AR

纯 parallel：

```
Heavy Backbone
    ↓
一次得到多个未来位置
```

完整 AR：

```
Heavy Model → t1
Heavy Model → t2
Heavy Model → t3
```

Semi-AR 可以理解为：

```
Heavy Parallel Backbone 只跑一次
          ↓
轻量 Sequential Module 在 block 内建依赖
          ↓
更稳定的 t1,t2,t3,... 候选
```

如果轻量 sequential 部分的成本远小于重新运行完整 Drafter，就可能在少量新增 latency 下显著改善后缀 quality。

### Prefix Survival Probability

假设每个候选位置有“到这里仍能通过”的概率：

$$
s_k=P(A\ge k)
$$

通常：

$$
s_1\ge s_2\ge ...\ge s_K
$$

如果模型还能预测 confidence：

$$
\hat s_k\approx P(A\ge k\mid features)
$$

那么系统就可以决定：

当 $\hat s_7$ 已经很低时，为什么还要让 Target 验证第 7～16 个位置？

### Confidence-Scheduled Verification

对请求 $r$ ，选择验证长度：

$$
K_r^*=\arg\max_K \frac{E[A_r(K)]}{T_V(K)+Cost_{capacity}(K)}
$$

其中 `Cost_capacity` 表示在线高并发下占用 verifier token budget 的机会成本。

因此两个相同 prompt 长度的请求也可能选择不同 $K$ ：

```
Request A：confidence 高 → verify 12
Request B：confidence 低 → verify 4
```

这比全局固定 `num_speculative_tokens=8` 更接近生产最优。

### 为什么要 Load-Aware

单请求 latency 最小化可能希望“多猜、多验”。

当系统高并发时：

```
Verifier batch capacity = 1024 positions
64 requests × 16 candidates = 1024
```

如果其中很多后缀注定被拒绝，整个 GPU 一轮被低价值 token 填满。

因此系统可以根据当前 load 调整策略：

- 低负载：允许更长 speculation，追求单用户速度；
- 高负载：更保守，减少低置信候选，保护总吞吐；
- 交互 SLO 紧：优先高价值短 block；
- 离线任务：允许更激进的 throughput policy。

### 这已经不只是一个“模型算法”

DSpark 类方法开始把以下信息联动：

- Drafter confidence；
- request state；
- Target engine throughput profile；
- 当前 batch/load；
- latency target。

这意味着 Speculator Policy 会成为 Runtime/Serving 的一部分，而不是纯 checkpoint 能决定的静态行为。

这也是第 09 课的核心。

策略迟滞的资源账要拆成计算、显存、内存带宽、主机开销和同步等待。高负载时 Target 容量更稀缺而策略应缩短验证通常只先改变其中几项，其他资源随后可能进入关键路径。策略迟滞的请求时间线和资源曲线可以呈现这种转移，平均 GPU 利用率只作为辅助信号。

对策略迟滞的优化只有在输出合同不变时才有效。Token 序列、采样分布、结构合法性、结束原因和错误传播均需对账。提前停止过早损失潜在收益会触发停止与回退，系统恢复到已有证据支持的配置。

## 失败模式与故障诊断

### 失败模式 1：高置信候选仍因域漂移被拒绝

针对“高置信候选仍因域漂移被拒绝”，保留失败现场并核验请求身份、模型修订、策略、负载分布与统计窗口。DSpark 置信度调度的时间线配合校准误差、前缀存活概率可区分选择错误、执行异常、验证失败和计量偏差。三方完成数无法对齐时不发布性能判断。

对“高置信候选仍因域漂移被拒绝”先执行在线保护，再处理复发条件。面向高置信候选仍因域漂移被拒绝的保护从禁用候选、预算收缩、请求隔离、过载拒绝和稳定回退中选择；长期措施落实到校验、迟滞、版本绑定、容量余量或自动门禁。原样本重放时同时检查验证器利用率的采集完整性。

### 失败模式 2：阈值追逐瞬时负载产生振荡

“阈值追逐瞬时负载产生振荡”的排查从证据一致性开始：请求、模型、策略、输入输出分布和测量窗口必须对应同一次运行。检查半自回归草拟的阶段事件，并用前缀存活概率及动态深度分布缩小故障位置。客户端、服务端、计费数据均需完成对账。

修复“阈值追逐瞬时负载产生振荡”分为影响控制和复验。针对阈值追逐瞬时负载产生振荡可以撤回候选、降低预算、隔离请求、拒绝过载或切换稳定路径；复发预防补齐输入校验、迟滞、版本绑定、容量余量及门禁。重放同一失败样本后，核对策略切换次数没有被隐藏。

### 失败模式 3：低负载策略在高负载下占满验证器

记录到“低负载策略在高负载下占满验证器”时，冻结配置和工作负载，确认请求身份、模型及策略修订、长度分布和时间窗口。沿前缀存活概率回放事件，再比较动态深度分布与验证器利用率。若完成数存在账差，先修复计量链。

处理“低负载策略在高负载下占满验证器”时先保护在线请求，可采用禁用候选、收紧预算、隔离请求、拒绝过载或回退稳定路径。后续通过输入校验、迟滞、版本绑定、容量余量或自动门禁降低复发概率。修复完成后重放原失败样本，并确认接受长度没有转移到未计量层。

### 失败模式 4：校准数据不覆盖长上下文

排查“校准数据不覆盖长上下文”需要同一版本、同一请求分布和同一统计窗口。先复核请求身份、模型与策略，再查看动态验证长度的时间线以及验证器利用率、策略切换次数。选择、执行、验证、计量四个环节逐一排除，并核对三方完成数。

“校准数据不覆盖长上下文”的即时动作是限制影响面：撤掉候选、缩小预算、隔离流量、执行过载拒绝或恢复稳定修订。根因修复需补充适用的输入检查、迟滞、版本关系、资源余量和门禁。随后用同一失败输入复验 Goodput。

### 失败模式 5：提前停止过早损失潜在收益

诊断“提前停止过早损失潜在收益”时，先核对请求身份、模型修订、策略配置、输入输出分布和测量窗口。沿时间线检查负载感知策略，结合策略切换次数与接受长度定位工作选择、执行、验证或计量环节。客户端、服务端和计费完成数未对账前暂停性能结论。

对“提前停止过早损失潜在收益”先执行在线保护，再处理复发条件。面向提前停止过早损失潜在收益的保护从禁用候选、预算收缩、请求隔离、过载拒绝和稳定回退中选择；长期措施落实到校验、迟滞、版本绑定、容量余量或自动门禁。原样本重放时同时检查 P99 的采集完整性。

### 失败模式 6：策略日志缺少决策输入

出现“策略日志缺少决策输入”后，固定当前请求集和版本信息，检查模型、策略、输入输出分布及测量窗口是否一致。随后沿置信度校准的事件查看接受长度和 Goodput，确定问题落在选择、执行、验证还是计量。完成数对账是继续分析的前提。

修复“策略日志缺少决策输入”分为影响控制和复验。针对策略日志缺少决策输入可以撤回候选、降低预算、隔离请求、拒绝过载或切换稳定路径；复发预防补齐输入校验、迟滞、版本绑定、容量余量及门禁。重放同一失败样本后，核对校准误差没有被隐藏。

```
"""Lesson 08 — confidence-gated draft scheduling with Target agreement labels."""

from __future__ import annotations

import argparse

from phase3lab.shared.cuda_ops import cuda_environment, load_causal_lm
from phase3lab.shared.runner import LabSpec, PreconditionError, run_cli

SPEC = LabSpec(
    lab_id="lesson-08-confidence-scheduler",
    title="DSpark：按 Draft 置信度决定是否提议",
    goal="在一组真实前缀上计算 Draft 置信度和 Target 一致性，再扫描调度阈值。",
    real_evidence=("draft probability", "draft/target token IDs", "threshold decisions"),
    required_inputs=("compatible draft and target models", "CUDA GPU"),
    outputs=("prefix-level labels", "threshold sweep", "coverage/agreement curve"),
    acceptance=("confidence comes from Draft logits", "agreement comes from Target", "threshold changes decisions"),
)

def add_arguments(parser: argparse.ArgumentParser) -> None:
    parser.add_argument("--draft-model", default="auto")
    parser.add_argument("--thresholds", default="0.2,0.4,0.6,0.8")

def parse_thresholds(raw: str) -> list[float]:
    values = [float(item) for item in raw.split(",") if item.strip()]
    if not values or any(value < 0 or value > 1 for value in values):
        raise ValueError("thresholds must be between zero and one")
    return sorted(set(values))

def evaluate_threshold(rows: list[dict], threshold: float) -> dict:
    selected = [row for row in rows if row["draft_confidence"] >= threshold]
    accepted = [row for row in selected if row["agrees_with_target"]]
    return {
        "threshold": threshold,
        "scheduled": len(selected),
        "coverage": round(len(selected) / max(len(rows), 1), 6),
        "agreement_when_scheduled": round(len(accepted) / max(len(selected), 1), 6),
    }

def fixture(args: argparse.Namespace) -> dict:
    rows = [
        {"prefix": "a", "draft_confidence": 0.91, "agrees_with_target": True},
        {"prefix": "b", "draft_confidence": 0.68, "agrees_with_target": False},
        {"prefix": "c", "draft_confidence": 0.37, "agrees_with_target": True},
        {"prefix": "d", "draft_confidence": 0.12, "agrees_with_target": False},
    ]
    return {"labels": rows, "sweep": [evaluate_threshold(rows, value) for value in parse_thresholds(args.thresholds)]}

def real(args: argparse.Namespace) -> dict:
    if args.model == "auto" or args.draft_model == "auto":
        raise PreconditionError("provide --model and --draft-model")
    if args.model == args.draft_model:
        raise PreconditionError("draft and target identifiers must differ")
    torch, tokenizer, target, target_load = load_causal_lm(args.model)
    _, draft_tokenizer, draft, draft_load = load_causal_lm(args.draft_model)
    if tokenizer.get_vocab() != draft_tokenizer.get_vocab():
        raise PreconditionError("draft and target tokenizers must have identical vocabularies")
    prefixes = [args.prompt + suffix for suffix in ("", "\n给出反例。", "\n输出两点。", "\n只回答一句。")]
    rows = []
    with torch.inference_mode():
        for index, prefix in enumerate(prefixes):
            ids = tokenizer(prefix, return_tensors="pt").input_ids.to("cuda")
            draft_probabilities = torch.softmax(draft(ids, use_cache=True).logits[:, -1, :].float(), dim=-1)
            confidence, draft_id = torch.max(draft_probabilities, dim=-1)
            target_id = torch.argmax(target(ids, use_cache=True).logits[:, -1, :], dim=-1)
            rows.append({
                "prefix_index": index,
                "prefix_tokens": int(ids.shape[1]),
                "draft_token_id": int(draft_id.item()),
                "target_token_id": int(target_id.item()),
                "draft_confidence": round(float(confidence.item()), 8),
                "agrees_with_target": bool(draft_id.item() == target_id.item()),
            })
    return {
        "environment": cuda_environment(torch),
        "load_ms": {"target": target_load, "draft": draft_load},
        "labels": rows,
        "sweep": [evaluate_threshold(rows, value) for value in parse_thresholds(args.thresholds)],
    }

def main() -> None:
    run_cli(SPEC, add_arguments, real, fixture)

if __name__ == "__main__":
    main()
```
