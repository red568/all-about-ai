## 课程定位

本课把 EAGLE-3：Training-Time Test 与直接 Token 预测放回真实请求链路中讨论，中心问题为“EAGLE-3 如何通过直接预测与多层特征融合提高接受长度？”。EAGLE-3 Drafter 和直接 Token 预测提供分析入口，计算模型负责说明方向，实验和发布门禁负责限定结论。评审时需要同时查看模型版本、负载、调度、显存、并发与服务等级，避免把 EAGLE-3 Drafter 的局部理想收益直接当成端到端结果。

本课先用 CPU 模拟控制 EAGLE-3 Drafter 和直接 Token 预测，再用真实 CUDA 路径检查这些关系进入实现后增加了哪些成本。每份结果都要标明数据来源、运行环境和适用边界。这样得到的是可复查的工程判断，而非依赖某个框架版本的参数口诀。

## 知识串讲

### 核心直觉与基础关系

### 核心直觉：从“预测未来特征”到“预测可验证 Token”

假设 Target Model 在当前上下文 $x_{1:t}$ 下产生隐藏状态：

$$
h_t^{(l)}=f_l(x_{1:t})
$$

早期思路希望 Drafter 预测未来隐藏状态：

$$
\hat h_{t+1}\approx h_{t+1}
$$

再从预测特征映射到 token。

问题是：

Feature 空间的距离变小，并不保证最终 token 排名一定更接近 Target。

对于 speculative decoding，真正产生收益的是 Target 最终接受多少 token，而不是 hidden vector 的欧氏距离有多漂亮。

因此可以把训练目标更直接地写成未来 token 的交叉熵：

$$
\mathcal L_{draft}=-\sum_{j=1}^{K}\log q_\theta(x_{t+j}\mid features, draft\ context)
$$

这里 $q_\theta$ 是 Drafter。

### 为什么需要 Target 的多层特征

Transformer 不同层包含的信息不同：

- 较浅层更接近词法/局部信息；
- 中间层形成组合语义；
- 深层更接近最终 next-token 决策。

如果 Drafter 只接最终一层，可能丢失一些对未来 rollout 有帮助的中间信号。

一种抽象表达：

$$
z_t = \phi(h_t^{(l_1)},h_t^{(l_2)},...,h_t^{(l_m)})
$$

再由：

$$
q_\theta(x_{t+1:t+K}\mid z_t)
$$

提出候选。

$\phi$ 可以是拼接、投影、加权或专门的 fusion 模块。工程上真正要关注的不是公式形态，而是：\*\*Target feature 获取本身会不会增加数据存储、通信和训练开销。\*\*

### Training-Time Test 的直觉

普通蒸馏往往先构造“正确答案”，再让学生模型逼近。

Speculator 的特殊点在于：

训练时最好让 Drafter 看到自己推出来的状态，而不是永远只在完美 teacher prefix 上学习。

因为上线后 Drafter 的第 2、3、4 个候选是建立在它自己前面预测的候选之上。

如果训练只看 ground-truth prefix，就会出现 exposure mismatch：

```
训练：永远从正确前缀继续
上线：经常从自己猜出的前缀继续
```

Training-Time Test 可以理解为：训练阶段主动运行/测试 Drafter，让训练样本更接近真实 speculative rollout 分布。

### EAGLE-3 的性能模型

对 EAGLE-3，我们仍使用第 01 课的统一模型：

$$
T_{effective}=\frac{T_{draft}+T_{verify}+T_{other}}{E[A]}
$$

EAGLE-3 优化的重点不是让 $T_{draft}$ 变成 0，而是用更好的候选质量提高 $E[A]$ ，同时保持 Drafter 足够小。

因此训练一个 Speculator 时，不要只看 validation loss。至少同时记录：

- top-1 token accuracy；
- position-wise accuracy；
- mean accepted length；
- tree acceptance；
- draft ms/round；
- verify ms/round；
- end-to-end TPOT。

### Position-wise Accuracy 为什么重要

假设未来 5 个位置准确率是：

```
pos1: 90%
pos2: 75%
pos3: 58%
pos4: 40%
pos5: 25%
```

如果验证要求最长正确前缀，第 4/5 位置的低准确率未必能转化为多少收益。

更重要的是 prefix survival：

$$
P(A\ge k)=P(d_1\ accepted,...,d_k\ accepted)
$$

平均 accepted length 可写为：

$$
E[A]=\sum_{k\ge1}P(A\ge k)
$$

这比“所有位置平均准确率”更接近真实加速收益。

### 训练与数据工程

EAGLE-3 类训练通常需要 Target 输出的隐藏状态，因此工程管线可以分两种：

### Offline Features

先跑 Target，把特征保存到磁盘：

优点：Drafter 训练时不需要持续加载 Target。

缺点：

- 特征数据可能巨大；
- 数据集、Target revision、层选择改变后需要重建；
- I/O 可能变成训练瓶颈。

### Online Features

训练时按需运行 Target 产生 feature。

优点：数据新鲜、流程简单、易做在线采样。

缺点：Target forward 显著增加训练成本。

选择取决于训练规模、存储、Target 大小和迭代速度。

### 直接 Token 预测

对直接 Token 预测做边界检查，要覆盖输入、输出、状态归属和销毁时点。EAGLE-3：Training-Time Test 与直接 Token 预测的等待、计算及复制都能沿这些节点定位。直接 Token 预测传给 Target 多层特征融合的数据还应附带模型或策略版本，使测量结果可以对应到唯一配置。

直接 Token 预测的资源账要拆成计算、显存、内存带宽、主机开销和同步等待。训练阶段模拟推理期递归状态以缩小暴露偏差通常只先改变其中几项，其他资源随后可能进入关键路径。直接 Token 预测的请求时间线和资源曲线可以呈现这种转移，平均 GPU 利用率只作为辅助信号。

工作负载一变，直接 Token 预测对系统的贡献也会变化。按域训练或共享 Drafter 应覆盖长短输入、不同输出、并发、突发、采样与任务域，并保留低载、稳定高载和过载记录。容量判断不能从一次固定批量的短运行外推。

对直接 Token 预测的优化只有在输出合同不变时才有效。Token 序列、采样分布、结构合法性、结束原因和错误传播均需对账。代码域收益无法迁移到开放聊天会触发停止与回退，系统恢复到已有证据支持的配置。

直接 Token 预测相关事件要能关联到稳定请求身份、模型与策略版本、开始结束时间、阶段耗时、资源采样和失败原因。端到端加速比必须附带口径。缺少这些信息时，关于“EAGLE-3 如何通过直接预测与多层特征融合提高接受长度？”的判断无法在上线后复核。

### Training-Time Test

设置树宽和验证预算解决哪项用户问题，需要由 Target 验证延迟、显存增量和位置级 Token 准确率共同证明。评审材料同时记录位置级准确率资源账、“Drafter 容量与延迟共同决定端到端收益”生效条件和代码域收益无法迁移到开放聊天的门禁。启用范围与实际证据范围保持一致。

围绕“设置树宽和验证预算”运行基线、候选与回退。候选只引入“设置树宽和验证预算”研究变量，回退保持已验证制品可立即恢复；每组使用同一请求集合和随机种子。报告分开呈现“设置树宽和验证预算”在不同负载及请求形态下的结果，并记录拒绝项、复查触发器和域外退化是否足以支付维护开销。

### 决策 6：制定模型与 Drafter 兼容矩阵

决定“制定模型与 Drafter 兼容矩阵”是否上线时，服务承诺是评审起点，端到端加速比、域外退化、平均接受长度构成结果证据。还需解释特征归一化与投影怎样变化、“服务域漂移会改变接受长度分布”在哪些负载下有效，以及遇到只复述论文速度比而没有本机基线时如何停止。

### 失败模式 1：平均准确率掩盖后部位置崩塌

针对“平均准确率掩盖后部位置崩塌”，保留失败现场并核验请求身份、模型修订、策略、负载分布与统计窗口。EAGLE-3 Drafter 的时间线配合位置级 Token 准确率、平均接受长度可区分选择错误、执行异常、验证失败和计量偏差。三方完成数无法对齐时不发布性能判断。

处理“平均准确率掩盖后部位置崩塌”时先保护在线请求，可采用禁用候选、收紧预算、隔离请求、拒绝过载或回退稳定路径。后续通过输入校验、迟滞、版本绑定、容量余量或自动门禁降低复发概率。修复完成后重放原失败样本，并确认 Drafter 延迟没有转移到未计量层。

### 失败模式 2：训练期教师特征与服务期递归特征不一致

“训练期教师特征与服务期递归特征不一致”的排查从证据一致性开始：请求、模型、策略、输入输出分布和测量窗口必须对应同一次运行。检查直接 Token 预测的阶段事件，并用平均接受长度及树节点利用率缩小故障位置。客户端、服务端、计费数据均需完成对账。

“训练期教师特征与服务期递归特征不一致”的即时动作是限制影响面：撤掉候选、缩小预算、隔离流量、执行过载拒绝或恢复稳定修订。根因修复需补充适用的输入检查、迟滞、版本关系、资源余量和门禁。随后用同一失败输入复验 Target 验证延迟。

### 失败模式 3：特征层选择增加带宽而收益有限

记录到“特征层选择增加带宽而收益有限”时，冻结配置和工作负载，确认请求身份、模型及策略修订、长度分布和时间窗口。沿 Target 多层特征融合回放事件，再比较树节点利用率与 Drafter 延迟。若完成数存在账差，先修复计量链。

对“特征层选择增加带宽而收益有限”先执行在线保护，再处理复发条件。面向特征层选择增加带宽而收益有限的保护从禁用候选、预算收缩、请求隔离、过载拒绝和稳定回退中选择；长期措施落实到校验、迟滞、版本绑定、容量余量或自动门禁。原样本重放时同时检查端到端加速比的采集完整性。

### 失败模式 4：Drafter 版本与 Target 修订不匹配

排查“Drafter 版本与 Target 修订不匹配”需要同一版本、同一请求分布和同一统计窗口。先复核请求身份、模型与策略，再查看 Training-Time Test 的时间线以及 Drafter 延迟、Target 验证延迟。选择、执行、验证、计量四个环节逐一排除，并核对三方完成数。

修复“Drafter 版本与 Target 修订不匹配”分为影响控制和复验。针对 Drafter 版本与 Target 修订不匹配可以撤回候选、降低预算、隔离请求、拒绝过载或切换稳定路径；复发预防补齐输入校验、迟滞、版本绑定、容量余量及门禁。重放同一失败样本后，核对显存增量没有被隐藏。

### 失败模式 5：代码域收益无法迁移到开放聊天

诊断“代码域收益无法迁移到开放聊天”时，先核对请求身份、模型修订、策略配置、输入输出分布和测量窗口。沿时间线检查位置级准确率，结合 Target 验证延迟与端到端加速比定位工作选择、执行、验证或计量环节。客户端、服务端和计费完成数未对账前暂停性能结论。

处理“代码域收益无法迁移到开放聊天”时先保护在线请求，可采用禁用候选、收紧预算、隔离请求、拒绝过载或回退稳定路径。后续通过输入校验、迟滞、版本绑定、容量余量或自动门禁降低复发概率。修复完成后重放原失败样本，并确认域外退化没有转移到未计量层。

### 失败模式 6：只复述论文速度比而没有本机基线

出现“只复述论文速度比而没有本机基线”后，固定当前请求集和版本信息，检查模型、策略、输入输出分布及测量窗口是否一致。随后沿特征归一化与投影的事件查看端到端加速比和显存增量，确定问题落在选择、执行、验证还是计量。完成数对账是继续分析的前提。

```
"""Lesson 02 — inspect and time an EAGLE-style multi-layer feature path."""

from __future__ import annotations

import argparse

from phase3lab.shared.cuda_ops import cuda_environment, load_causal_lm, memory_snapshot, timed_cuda
from phase3lab.shared.runner import LabSpec, run_cli
from phase3lab.shared.stats import latency_summary

SPEC = LabSpec(
    lab_id="lesson-02-eagle-feature-path",
    title="EAGLE-3：多层 Target 特征抽取与融合路径",
    goal="验证选层、张量形状、融合投影和额外显存，而不把随机投影当作已训练 Drafter。",
    real_evidence=("selected hidden-state shapes", "fusion latency", "allocator delta"),
    required_inputs=("hidden-state capable causal LM", "CUDA GPU"),
    outputs=("layer map", "projection timing", "memory evidence"),
    acceptance=("layer indices resolve", "batch/sequence dimensions agree", "report labels projection as untrained"),
)

def add_arguments(parser: argparse.ArgumentParser) -> None:
    parser.add_argument("--layers", default="-1,-4,-8")
    parser.add_argument("--projection-width", type=int, default=512)
    parser.add_argument("--repeats", type=int, default=10)

def resolve_layers(raw: str, count: int) -> list[int]:
    requested = [int(value) for value in raw.split(",") if value.strip()]
    if len(set(requested)) < 2:
        raise ValueError("--layers must select at least two distinct layers")
    resolved = [value if value >= 0 else count + value for value in requested]
    if any(value < 0 or value >= count for value in resolved):
        raise ValueError(f"layer selection exceeds available hidden states: {count}")
    return resolved

def fixture(args: argparse.Namespace) -> dict:
    resolved = resolve_layers(args.layers, 25)
    hidden = 896
    return {
        "available_hidden_states": 25,
        "selected": resolved,
        "concatenated_width": hidden * len(resolved),
        "projection_shape": [hidden * len(resolved), args.projection_width],
        "trained": False,
    }

def real(args: argparse.Namespace) -> dict:
    if args.projection_width < 1:
        raise ValueError("--projection-width must be positive")
    torch, tokenizer, model, load = load_causal_lm(args.model)
    inputs = tokenizer(args.prompt, return_tensors="pt").to("cuda")
    with torch.inference_mode():
        outputs = model(**inputs, output_hidden_states=True, use_cache=False)
    hidden_states = outputs.hidden_states
    selected_indices = resolve_layers(args.layers, len(hidden_states))
    selected = [hidden_states[index] for index in selected_indices]
    shape_pairs = {(int(value.shape[0]), int(value.shape[1])) for value in selected}
    if len(shape_pairs) != 1:
        raise RuntimeError("selected hidden states disagree on batch/sequence dimensions")
    concatenated = torch.cat(selected, dim=-1)
    projection = torch.nn.Linear(concatenated.shape[-1], args.projection_width, bias=False, device="cuda", dtype=concatenated.dtype)
    before = memory_snapshot(torch)
    samples, fused = timed_cuda(torch, lambda: projection(concatenated), warmups=2, repeats=args.repeats)
    after = memory_snapshot(torch)
    return {
        "environment": cuda_environment(torch),
        "load_ms": load,
        "selected_layers": selected_indices,
        "hidden_shapes": [list(value.shape) for value in selected],
        "concatenated_shape": list(concatenated.shape),
        "fused_shape": list(fused.shape),
        "fusion_latency": latency_summary(samples),
        "memory_before": before,
        "memory_after": after,
        "projection_trained": False,
        "measurement_note": "this measures the feature interface and cost; Drafter quality requires a compatible trained EAGLE checkpoint",
    }

def main() -> None:
    run_cli(SPEC, add_arguments, real, fixture)

if __name__ == "__main__":
    main()
```
