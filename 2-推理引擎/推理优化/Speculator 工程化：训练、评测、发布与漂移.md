“如何把 Speculator 当作独立制品管理，并用真实流量持续选择策略？”贯穿本课。先把 Speculator 独立制品、训练数据版本及其状态边界讲清楚，再讨论计算、实现和上线证据。在 Speculator 工程化：训练、评测、发布与漂移中，算法选择只是决策的一部分；负载分布、模型修订、调度、显存、并发和服务等级都会改变结论。每项收益都需要对应可观察的事件与适用范围。

### 核心直觉：Speculator 不是模型附件，而是需要独立生命周期的 Serving 组件

真正工程化后，Speculator 的问题不再只是“能不能产生候选”，而是训练数据来自哪里、如何评测、怎样与 Target revision 绑定、何时灰度、何时回退。下面先从训练数据开始。

候选源：

1. 通用 instruction 数据；
2. coding/math 专项数据；
3. 真实匿名化 serving trace；
4. online teacher rollout；
5. 结构化输出/工具调用数据。

对于 Speculator，数据分布的优先级非常高，因为 acceptance 直接依赖：

$$
P_{serve}(x_{future}\mid context)
$$

如果训练和 Serving 分布偏移：

$$
D_{KL}(P_{serve}\|P_{train})\uparrow
$$

通常会表现为 position-wise acceptance 下降。

### 动态 Speculator Policy

可以定义候选：

```
No speculation
MTP
EAGLE-3
P-EAGLE
DFlash
DSpark
```

Policy 输入：

- model id；
- adapter id；
- request domain；
- prompt length；
- expected output；
- current concurrency；
- recent acceptance；
- SLO tier。

Policy 输出：

- algorithm；
- draft depth/block size；
- verification budget。

一个简单评分：

$$
Score_j=PredictedSavedTime_j-\lambda_1 VerifyCost_j-\lambda_2 MemoryCost_j
$$

选择：

$$
j^*=\arg\max_j Score_j
$$

如果所有 $Score_j\le0$ ，直接关闭 speculation。

### Acceptance Drift

Speculator 上线后可能出现：

- 模型版本变化；
- 用户业务域变化；
- 新 LoRA 上线；
- Prompt template 改变；
- Sampling 参数改变。

导致：

$$
Acceptance_{online}\downarrow
$$

因此监控至少按：

- model；
- adapter；
- tenant/domain；
- concurrency bucket；
- algorithm；

切分。

只有全局平均 acceptance，可能完全看不出某个大客户已经退化。

### Canary Speculator

上线新 Speculator 不需要直接 100%。

流程：

```
5% traffic
  ↓
检查正确性 / P99 / acceptance / GPU cost
  ↓
25%
  ↓
50%
  ↓
100%
```

Rollback 条件可以是：

- accepted length 低于基线；
- TPOT 恶化；
- verifier waste 超阈值；
- error/correctness 异常；
- 显存抬高导致稳定并发下降。

### 离线评测矩阵

对离线评测矩阵做边界检查，要覆盖输入、输出、状态归属和销毁时点。Speculator 工程化：训练、评测、发布与漂移的等待、计算及复制都能沿这些节点定位。离线评测矩阵传给在线策略选择的数据还应附带模型或策略版本，使测量结果可以对应到唯一配置。

离线评测矩阵的资源账要拆成计算、显存、内存带宽、主机开销和同步等待。在线选择器根据请求特征和容量决定策略通常只先改变其中几项，其他资源随后可能进入关键路径。离线评测矩阵的请求时间线和资源曲线可以呈现这种转移，平均 GPU 利用率只作为辅助信号。

离线评测矩阵相关事件要能关联到稳定请求身份、模型与策略版本、开始结束时间、阶段耗时、资源采样和失败原因。回滚时间必须附带口径。缺少这些信息时，关于“如何把 Speculator 当作独立制品管理，并用真实流量持续选择策略？”的判断无法在上线后复核。

### 在线策略选择

在 Speculator 工程化：训练、评测、发布与漂移中，在线策略选择的边界由输入、输出、状态和拥有者共同确定。把生命周期写清楚，才能定位请求在哪个阶段等待、计算或复制。在线策略选择连接 Target 兼容关系时还要传播身份和版本，避免把另一套配置的结果归到当前实验。

测量在线策略选择时分别记录算力、显存、带宽、CPU 开销与同步。发生“数据漂移会改变位置接受率与域收益”后，缩短的阶段可能让另一项资源成为瓶颈。分析因此对齐在线策略选择的阶段事件和资源轨迹，不让单个平均利用率代替因果证据。

评估在线策略选择需要把负载分布写入实验：输入输出长度、并发、到达突发、采样方式和业务域都可能移动收益边界。制定灰度和回滚流程至少比较低载、临近容量与过载，结论只覆盖实际运行过的区间。

观察在线策略选择需要稳定请求身份、模型与策略修订、起止时间、阶段耗时、资源快照和失败原因。制品加载成本同时注明单位、窗口和分母。这些字段使“如何把 Speculator 当作独立制品管理，并用真实流量持续选择策略？”可以在发布后按原条件回放。

## 工程决策与取舍

### 决策 1：定义制品元数据

“定义制品元数据”进入方案评审前，要绑定具体服务承诺和兼容组合通过率、策略命中率、漂移分数。资源侧检查 Speculator 独立制品，机制侧限定“Drafter 收益由模型、域、采样和负载共同决定”，故障侧为 Drafter 与 Target 修订错配准备停止动作。测试样本不代表业务时，结论只覆盖该样本。

验证“定义制品元数据”需要三条可复现路径：已确认的基线、只改“定义制品元数据”因素的候选、无需重新取大制品的回退。三者共享请求和随机种子，数据按负载区间与请求形态统计。最终文档保存“定义制品元数据”的取舍理由、有效期和制品加载成本相对维护成本的变化。

### 决策 2：构建训练与评测数据谱系

构建训练与评测数据谱系解决哪项用户问题，需要由域级接受长度、在线净收益和灰度错误率共同证明。评审材料同时记录训练数据版本资源账、“独立版本允许 Target 与 Speculator 解耦发布但扩大兼容矩阵”生效条件和离线集合过度代表单一域的门禁。启用范围与实际证据范围保持一致。

围绕“构建训练与评测数据谱系”运行基线、候选与回退。候选只引入“构建训练与评测数据谱系”研究变量，回退保持已验证制品可立即恢复；每组使用同一请求集合和随机种子。报告分开呈现“构建训练与评测数据谱系”在不同负载及请求形态下的结果，并记录拒绝项、复查触发器和制品加载成本是否足以支付维护开销。

### 决策 3：设计离线门禁

决定“设计离线门禁”是否上线时，服务承诺是评审起点，策略命中率、漂移分数、回滚时间构成结果证据。还需解释离线评测矩阵怎样变化、“离线接受率必须连接到真实服务成本”在哪些负载下有效，以及遇到在线选择器使用不可观测特征时如何停止。

“设计离线门禁”比较基线、候选和回退三种配置。基线沿用已验证路径，候选只改变“设计离线门禁”研究因素，回退无需重新下载大制品即可恢复服务。三组使用相同请求集合与随机种子，并按负载区间、请求形态分组。决策记录包含“设计离线门禁”的选择理由、被拒方案、结论到期条件和制品加载成本对应的维护成本。

### 决策 4：选择在线策略特征

评审“选择在线策略特征”时，先写明要改善的用户承诺，以及对应的在线净收益、灰度错误率和制品加载成本。候选需说明在线策略选择的资源变化、“在线选择器根据请求特征和容量决定策略”的适用条件及漂移告警只看平均接受率触发的停止动作。只在极端样本成立的收益应限定启用范围。

实验为“选择在线策略特征”保留当前基线、单变量候选和暖回退。请求集与随机种子保持一致，结果按负载和请求类型拆开。评审说明“选择在线策略特征”为何采用当前方案、其他方案为何未采用、什么变化会让结论失效，以及制品加载成本的改善是否覆盖新增运维成本。

### 决策 5：设置漂移阈值

“设置漂移阈值”进入方案评审前，要绑定具体服务承诺和漂移分数、回滚时间、兼容组合通过率。资源侧检查 Target 兼容关系，机制侧限定“数据漂移会改变位置接受率与域收益”，故障侧为回滚时旧 Drafter 已被逐出准备停止动作。测试样本不代表业务时，结论只覆盖该样本。

验证“设置漂移阈值”需要三条可复现路径：已确认的基线、只改“设置漂移阈值”因素的候选、无需重新取大制品的回退。三者共享请求和随机种子，数据按负载区间与请求形态统计。最终文档保存“设置漂移阈值”的取舍理由、有效期和制品加载成本相对维护成本的变化。

### 决策 6：制定灰度和回滚流程

制定灰度和回滚流程解决哪项用户问题，需要由灰度错误率、制品加载成本和域级接受长度共同证明。评审材料同时记录灰度发布资源账、“灰度和回滚需要保留可复现制品身份”生效条件和发布记录无法关联训练数据的门禁。启用范围与实际证据范围保持一致。

围绕“制定灰度和回滚流程”运行基线、候选与回退。候选只引入“制定灰度和回滚流程”研究变量，回退保持已验证制品可立即恢复；每组使用同一请求集合和随机种子。报告分开呈现“制定灰度和回滚流程”在不同负载及请求形态下的结果，并记录拒绝项、复查触发器和制品加载成本是否足以支付维护开销。

## 失败模式与故障诊断

### 失败模式 1：Drafter 与 Target 修订错配

“Drafter 与 Target 修订错配”的排查从证据一致性开始：请求、模型、策略、输入输出分布和测量窗口必须对应同一次运行。检查 Speculator 独立制品的阶段事件，并用兼容组合通过率及域级接受长度缩小故障位置。客户端、服务端、计费数据均需完成对账。

修复“Drafter 与 Target 修订错配”分为影响控制和复验。针对 Drafter 与 Target 修订错配可以撤回候选、降低预算、隔离请求、拒绝过载或切换稳定路径；复发预防补齐输入校验、迟滞、版本绑定、容量余量及门禁。重放同一失败样本后，核对在线净收益没有被隐藏。

### 失败模式 2：离线集合过度代表单一域

记录到“离线集合过度代表单一域”时，冻结配置和工作负载，确认请求身份、模型及策略修订、长度分布和时间窗口。沿训练数据版本回放事件，再比较域级接受长度与策略命中率。若完成数存在账差，先修复计量链。

处理“离线集合过度代表单一域”时先保护在线请求，可采用禁用候选、收紧预算、隔离请求、拒绝过载或回退稳定路径。后续通过输入校验、迟滞、版本绑定、容量余量或自动门禁降低复发概率。修复完成后重放原失败样本，并确认漂移分数没有转移到未计量层。

### 失败模式 3：在线选择器使用不可观测特征

排查“在线选择器使用不可观测特征”需要同一版本、同一请求分布和同一统计窗口。先复核请求身份、模型与策略，再查看离线评测矩阵的时间线以及策略命中率、在线净收益。选择、执行、验证、计量四个环节逐一排除，并核对三方完成数。

“在线选择器使用不可观测特征”的即时动作是限制影响面：撤掉候选、缩小预算、隔离流量、执行过载拒绝或恢复稳定修订。根因修复需补充适用的输入检查、迟滞、版本关系、资源余量和门禁。随后用同一失败输入复验灰度错误率。

### 失败模式 4：漂移告警只看平均接受率

诊断“漂移告警只看平均接受率”时，先核对请求身份、模型修订、策略配置、输入输出分布和测量窗口。沿时间线检查在线策略选择，结合在线净收益与漂移分数定位工作选择、执行、验证或计量环节。客户端、服务端和计费完成数未对账前暂停性能结论。

对“漂移告警只看平均接受率”先执行在线保护，再处理复发条件。面向漂移告警只看平均接受率的保护从禁用候选、预算收缩、请求隔离、过载拒绝和稳定回退中选择；长期措施落实到校验、迟滞、版本绑定、容量余量或自动门禁。原样本重放时同时检查回滚时间的采集完整性。

### 失败模式 5：回滚时旧 Drafter 已被逐出

出现“回滚时旧 Drafter 已被逐出”后，固定当前请求集和版本信息，检查模型、策略、输入输出分布及测量窗口是否一致。随后沿 Target 兼容关系的事件查看漂移分数和灰度错误率，确定问题落在选择、执行、验证还是计量。完成数对账是继续分析的前提。

修复“回滚时旧 Drafter 已被逐出”分为影响控制和复验。针对回滚时旧 Drafter 已被逐出可以撤回候选、降低预算、隔离请求、拒绝过载或切换稳定路径；复发预防补齐输入校验、迟滞、版本绑定、容量余量及门禁。重放同一失败样本后，核对制品加载成本没有被隐藏。

### 失败模式 6：发布记录无法关联训练数据

针对“发布记录无法关联训练数据”，保留失败现场并核验请求身份、模型修订、策略、负载分布与统计窗口。灰度发布的时间线配合灰度错误率、回滚时间可区分选择错误、执行异常、验证失败和计量偏差。三方完成数无法对齐时不发布性能判断。

处理“发布记录无法关联训练数据”时先保护在线请求，可采用禁用候选、收紧预算、隔离请求、拒绝过载或回退稳定路径。后续通过输入校验、迟滞、版本绑定、容量余量或自动门禁降低复发概率。修复完成后重放原失败样本，并确认兼容组合通过率没有转移到未计量层。

```
"""Lesson 09 — bind a Speculator artifact to a candidate endpoint and compare it."""

from __future__ import annotations

import argparse
import hashlib
import json
from pathlib import Path

from phase3lab.shared.evidence import require_distinct_endpoints, summarize_records
from phase3lab.shared.http_client import completion, discover_models, metrics_evidence
from phase3lab.shared.runner import LabSpec, PreconditionError, require_count, run_cli
from phase3lab.shared.stats import paired_delta

SPEC = LabSpec(
    lab_id="lesson-09-speculator-artifact",
    title="Speculator Artifact：版本绑定与双端点 Smoke Benchmark",
    goal="用制品清单把 candidate 服务绑定到 Target/Drafter 版本，再执行真实双端点配对请求。",
    real_evidence=("manifest hash", "two endpoint model lists", "paired request records"),
    required_inputs=("baseline endpoint", "candidate endpoint", "Speculator manifest JSON"),
    outputs=("artifact identity", "metrics evidence", "paired smoke result"),
    acceptance=("manifest target matches served model", "candidate is a distinct endpoint", "all pairs complete"),
)

def add_arguments(parser: argparse.ArgumentParser) -> None:
    parser.add_argument("--speculator-manifest", default="")

def load_manifest(path: str) -> tuple[dict, str]:
    target = Path(path)
    if not target.is_file():
        raise PreconditionError("--speculator-manifest must point to a JSON file")
    raw = target.read_bytes()
    value = json.loads(raw)
    required = {"artifact_id", "artifact_sha256", "target_model", "drafter_model", "revision"}
    missing = sorted(required - value.keys())
    if missing:
        raise ValueError(f"Speculator manifest is missing: {', '.join(missing)}")
    if len(str(value["artifact_sha256"])) != 64:
        raise ValueError("artifact_sha256 must be a 64-character SHA-256")
    return value, hashlib.sha256(raw).hexdigest()

def fixture(args: argparse.Namespace) -> dict:
    return {
        "artifact": {"artifact_id": "fixture-speculator", "target_model": "target-v1", "drafter_model": "draft-v1", "revision": "r3"},
        "endpoint_roles": ["baseline", "candidate-with-speculator"],
        "paired_delta": paired_delta([120, 118, 122], [102, 99, 105]),
        "attribution_complete": True,
    }

def real(args: argparse.Namespace) -> dict:
    require_count(args.base_url, 2, "Speculator artifact benchmark")
    if len(args.base_url) != 2:
        raise ValueError("provide exactly two --base-url values")
    require_distinct_endpoints(args.base_url)
    manifest, manifest_sha = load_manifest(args.speculator_manifest)
    endpoint_models = [discover_models(url) for url in args.base_url]
    model = manifest["target_model"] if args.model == "auto" else args.model
    if model != manifest["target_model"]:
        raise ValueError("--model differs from manifest target_model")
    if any(model not in values for values in endpoint_models):
        raise PreconditionError("manifest target_model is not served by both endpoints")
    evidence_urls = args.evidence_url or args.base_url
    if len(evidence_urls) != 2:
        raise ValueError("provide zero or exactly two --evidence-url values")
    metric_snapshots = [metrics_evidence(url) for url in evidence_urls]
    baseline_records = []
    candidate_records = []
    for index in range(args.requests):
        prompt = f"{args.prompt}\nartifact_case={index}"
        baseline_records.append(completion(args.base_url[0], model, prompt, args.max_new_tokens, request_id=f"artifact-{index}-base"))
        candidate_records.append(completion(args.base_url[1], model, prompt, args.max_new_tokens, request_id=f"artifact-{index}-candidate"))
    if not all(record.ok for record in baseline_records + candidate_records):
        raise RuntimeError("paired Speculator smoke requests did not all succeed")
    return {
        "artifact_manifest": manifest,
        "manifest_sha256": manifest_sha,
        "endpoint_models": endpoint_models,
        "metrics": metric_snapshots,
        "baseline": summarize_records(baseline_records),
        "candidate": summarize_records(candidate_records),
        "paired_delta": paired_delta([record.latency_ms for record in baseline_records], [record.latency_ms for record in candidate_records]),
        "records": {"baseline": [record.json() for record in baseline_records], "candidate": [record.json() for record in candidate_records]},
    }

def main() -> None:
    run_cli(SPEC, add_arguments, real, fixture)

if __name__ == "__main__":
    main()
```

## 联合推演 1：Speculator 独立制品、Drafter 收益由模型、域、采样和负载共同决定与定义制品元数据
